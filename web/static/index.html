01 · TRUSTED

Intent Contract

Compiled from the user's request only (never tool data), then frozen and SHA-256 hashed. Lists allowed effects (READ / WRITE / EGRESS / PAY / DELETE / ACCOUNT), typed slots and limits.

02 · UNTRUSTED

Planner LLM

Reads emails, files and web pages and proposes tool calls. We assume it can be fooled, so it has no authority of its own.

03 · TRUSTED

Warrant Gate

Deterministic reference monitor. Every sink argument (recipient, IBAN, file, URL, password) needs a warrant: USER_LITERAL, TRUSTED record, LOOKUP evidence or bounded DELEGATED content.

04 · TRUSTED

Shadow execution

Allowed calls first run on a deep copy of the environment. The state diff is checked against the effect envelope (egress/payment budgets, amount caps, deletes) before committing.

05 · PROBABILISTIC

Span Auditor + Ledger

Tool output is split into spans labelled EVIDENCE or DIRECTIVE (rules + small LLM). It can only narrow trust: directive values can never back a warrant. Everything lands in the Value Ledger and a JSONL audit log.

Detectors ask "is this text malicious?"

That is a probabilistic classifier race, and adaptive attackers win it. A missed span means a successful attack.

WARRANT asks "who authorised this value?"

Authority comes only from the user. Even if the planner is fully hijacked, an attacker's address, IBAN or URL has no warrant, so the action is refused with a typed reason and the agent continues the real task.

Drop-in for AgentDojo

Implemented as standard AgentDojo pipeline elements: ContractCompiler after InitQuery, and WarrantGate in place of ToolsExecutor. Same LLM, same tools, same benchmark.
